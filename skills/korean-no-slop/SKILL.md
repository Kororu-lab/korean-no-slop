# Korean No Slop

독자에게 필요한 내용과 사용자가 남기기로 한 내용으로 산출물을 구성한다. 생략한 문구와 비어 있는 선택 항목도 완성된 결과로 취급한다. 한국어 표현의 구조, 매체에 맞는 분량, 수정 지시의 이행을 함께 살핀다.

## 적용 방법

사용자의 현재 지시와 지정된 형식을 우선한다. 작성·패치·검토 중 요청한 작업을 수행하고, 한국어가 놓일 위치를 확인한다. 한 파일 안에서도 제목, 버튼, 본문, 발표자 노트의 형식은 각각 판단한다.

- UI·웹페이지: [ui.md](references/ui.md)
- 발표 슬라이드·프레젠테이션: [slides.md](references/slides.md)
- 보고서·문서·답변: [prose.md](references/prose.md)

해당 매체의 참고 문서만 읽는다. 별도의 산출물 제작 skill이나 프로젝트 규칙이 있다면 기존 제작 절차 안에서 이 규칙을 적용한다.

## 공통 규칙

### 1. 실제 내용을 직접 쓴다

주장, 상태, 행동부터 제시한다. 독자가 제기한 적 없는 오해를 만들어 정정하거나, 존재하지 않는 대안을 부정한 뒤 본론을 꺼내는 도입은 걷어낸다.

- `X가 아니라 Y입니다`, `단순한 X를 넘어 Y`, `X도 Y도 아닙니다`가 상투적인 장치라면 실제 내용만 남긴다.
- `…는 하지 않습니다`, `…는 필요 없습니다`로 요청하지 않은 비목표·장점을 만들어 열거한 문구는 생략한다.
- 사용자가 요청한 비교, 정확한 개념 구분, 지원 범위, 위험·제약을 전달하는 대조와 부정은 의미를 보존한다.

### 2. em dash로 문장을 장식하지 않는다

새로 쓰는 일반 한국어 설명에는 em dash(—)를 장식용 연결, 반전, 여운에 사용하지 않는다. 기존 문장의 양쪽 정보가 필요하면 자연스러운 접속 관계나 문장 분리로 잇는다. 한쪽이 군더더기면 그 구절을 덜어낸다.

문자만 콜론·하이픈·줄바꿈으로 치환하여 같은 수사 구조를 남기지 않는다. 직접 인용, 코드, 원문 표기, 사용자가 지정한 문학적 표현은 보존한다.

### 3. 설명은 역할이 있을 때 둔다

제목·부제·도움말·도입·요약·결론은 각자 필요한 정보를 제공할 때 둔다. 제목을 풀어 쓴 설명, 표를 다시 서술한 문단, 카드마다 대칭으로 붙인 소개문은 삭제 후보로 본다.

문구를 없앤 뒤 다른 말로 채우거나, 공간을 메우려고 새 주장·혜택을 만들지 않는다. 남겨야 할 사실이 있는 문구는 해당 위치의 목적에 맞게 줄이거나 옮긴다. 사용자가 삭제한 내용에는 아래 5번을 적용한다.

### 4. 매체에 맞는 단위로 쓴다

버튼·메뉴·슬라이드 항목은 짧은 레이블과 구절로 완성될 수 있다. 보고서 본문은 관계를 이해할 수 있는 문장으로 쓴다. 모든 항목을 완전한 문장으로 늘리거나 모든 본문을 명사 나열로 압축하지 않는다.

순서·비교·정보 관계가 형식을 결정하게 한다. 모든 섹션에 같은 수의 불릿, 소제목, 설명문을 맞출 필요는 없다.

### 5. 삭제한 내용은 빠진 상태로 유지한다

삭제 요청은 산출물의 범위를 바꾼다. 지목한 주제·문구·요소와 그 범위를 먼저 파악한 뒤, 그 범위에서 제거한다. 삭제 이유를 추론해 새 주장이나 정책으로 만들지 않는다.

- `A 비교를 빼줘`를 반영한 결과에는 A 비교, 비교 제외 선언, 제외를 정당화하는 설명이 남지 않는다.
- 삭제 범위에 속한 내용을 부제, 각주, 도움말, 발표자 노트, 다른 페이지로 옮겨 되살리지 않는다.
- 사용자가 `화면에서만 빼고 노트에는 남겨줘`처럼 위치를 지정하면 지정한 범위를 따른다.
- 편집 요청과 그 이행 과정은 산출물의 내용이 아니다. 수정 내역은 요청받았거나 검토에 필요한 경우에만 산출물 밖에서 짧게 알린다. 이유는 실제로 확인한 것만 쓴다.
- 삭제 범위가 모호하면 가장 좁은 명시 대상부터 고친다. 관련 없는 동작을 바꾸거나 실제 정보 손실·기능 충돌이 생기는 선택만 구체적으로 확인한다.

### 6. 의미와 기능을 보존한다

수치, 단위, 비교 기준, 인과관계, 불확실성, 필수 경고, 출처, 직접 인용, 제품 동작은 유지한다. `가능하다`를 `한다`로 바꾸거나, 추상적인 설명에 임의의 숫자·이유를 채워 넣지 않는다. 사용자 편집 지시의 대상과 의도는 그대로 반영한다.

문체 개선을 이유로 접근성 설명을 끊거나, 실제 제약을 숨기거나, 기능·계약을 변경하지 않는다. 필요한 정보와 요청한 삭제가 실제로 충돌하면 그 구체적인 지점만 설명한다.

## 새로 작성할 때

입력에서 확정한 내용과 사용자의 삭제·제외 지시를 먼저 반영한다. 매체에 필요한 요소만 선택해서 작성한다. 선택 항목은 생략할 수 있게 구성한다. 문구와 구성은 함께 검토한다.

## 기존 결과를 패치할 때

현행 파일과 사용자의 변경을 확인하고, 지목된 문구·요소 및 직접 연결된 레이아웃만 수정한다. 같은 문구가 여러 곳에 있더라도 요청 범위에 해당하는지 확인한다. UI의 불필요한 부제를 제거할 때는 필요에 따라 전용 여백과 참조도 함께 정리한다. 코드·문서 전체를 일괄 치환하지 않는다.

수정한 원본 형식으로 검증한다. UI·슬라이드는 실제 렌더링에서 제목, 본문, 여백과 잘림을 확인한다. 텍스트만 받은 경우에는 텍스트 검토의 범위로 보고한다.

## 출력 전 확인

- 요청한 정보와 의미, 매체의 기능이 남아 있는가?
- 불필요한 대조·부정 열거·em dash가 다른 형태로 남아 있는가?
- 부제·도움말·요약이 새로운 정보를 더하는가?
- 삭제 대상이 다른 위치나 제외 이유로 돌아왔는가?
- 편집 지시를 산출물 내용으로 옮겼는가?

통과하면 요청한 산출물을 전달한다. 검토만 요청받았다면 위치와 필요한 수정만 제시한다. 고칠 곳이 없으면 유지한다. AI 작성 여부나 검출기 회피 성능을 판정하지 않는다.

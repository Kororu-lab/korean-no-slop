# 보고서·문서·답변

독자가 판단하거나 실행하는 데 필요한 내용을 문장과 적절한 표·목록으로 전달한다. 제목·표의 항목과 본문의 호흡은 다르게 정할 수 있다.

## 구성

첫 문장에서 해당 문단의 내용을 시작한다. 사용자가 요구한 개요·요약·방법·한계 등은 유지한다. 각 절에 소개문, 본문을 반복하는 요약, 마지막 당부를 자동으로 붙이지 않는다.

조사한 과정은 재현이나 판단에 필요한 만큼만 담는다. 제품 소개에 개발 과정, 검토 보고에 요청하지 않은 비목표 목록, 최종 본문에 편집자의 지시를 섞지 않는다.

비교를 요청받았으면 비교한다. 개념의 오해를 바로잡는 것이 주제라면 대조를 사용한다. 문장의 설득력을 꾸미기 위해 새 대조 대상을 만들지 않는다. 실제 한계와 근거 있는 불확실성은 보존한다.

## 가상 사례

| 원문·상황 | 처리 |
| --- | --- |
| 이것은 단순한 목록이 아니라 팀의 가능성을 여는 기록입니다. | 실제 기능이 목록이면 그 기능을 직접 설명 |
| 성능 개선이 가능할 것으로 추정됩니다. | 추정 근거와 확실성 유지 |
| 해당 기능은 오프라인에서 작동하지 않습니다. | 사용자가 알아야 할 지원 범위이므로 유지 |
| 표의 모든 값을 앞뒤 문단에서 다시 나열 | 표를 남기고, 본문에는 해석·예외 등 추가 정보만 유지 |
| A 관련 문단을 삭제해 달라는 요청 | A의 내용과 A를 제외한 이유가 빠진 본문 작성 |

답변에서는 실제 결과를 먼저 알린다. 금지 사항을 준수했다는 선언, 검토했다는 반복 보고, 요청하지 않은 후속 제안으로 마지막 문단을 채우지 않는다.

# 평가 방법

`cases.json`의 입력을 새 문맥에서 skill과 함께 실행한다. `rubric.json`과 이전 결과는 실행자에게 제공하지 않는다. 출력 파일은 다음 형식으로 저장한다.

```json
{
  "metadata": {"date": "YYYY-MM-DD", "executor": "실행 환경", "kind": "독립 생성 또는 수동 예시"},
  "outputs": {"사례 ID": "실제로 생성한 결과 전문"}
}
```

`python3 scripts/check_cases.py 결과파일`은 누락·중복 사례, 필수 정보, 금지 문자열, 일부 그대로 유지해야 하는 사례를 확인한다. 다른 정확한 표현이 자동 검사에 걸리면 출력과 기준을 함께 검토한다. 통과 숫자는 문체 품질 점수나 AI 작성 확률을 뜻하지 않는다.

`rubric.json`의 `review` 항목은 사람이 출력과 원문을 대조해 판정한다. 필요한 비교·부정·부제·인용을 남기는 사례를 함께 실행한다. 실패한 입력과 출력은 보존하고, 규칙을 고친 뒤 같은 실패 및 인접한 보존 사례를 다시 확인한다.

이 묶음은 작은 합성 사례 집합이다. 한 실행에서 여러 사례를 처리하면 앞선 사례의 영향이 있을 수 있다. 독립 검증의 첫 회차는 이런 배치 실행으로 시작하고, 향후 중요한 회귀는 사례별 새 문맥으로 검증한다. 모델 간 효과나 skill 미적용 대비 개선은 별도 비교 실험이 필요하다.

실제 UI·PPTX의 패치는 소스 검사와 렌더링 검사를 모두 거친다. 이 초기 평가의 HTML 조각과 슬라이드 문구만으로 전체 UI·프레젠테이션의 시각적 품질을 검증했다고 보고하지 않는다.
